## Storage Contract

- The default Snapshot Payload retention is 30 days and the default Snapshot Storage Budget is 5 GiB; both are configurable through the common one-process and persistent CLI boundary.
- Admission counts all retained Snapshot Payload bytes plus every still-bound 32 MiB Preservation Budget before reserving another Retirement Unit. One shared launch lock makes that proof, reservation, and session persistence atomic across Issue Slice, Ad Hoc, and headless admissions. A unit does not start when the aggregate cannot fit.
- Capacity pressure reclaims only expired, unpinned payloads whose Retirement Unit is already `retired`. Ordering is deterministic by creation time and session id. Startup performs the same eligible sweep. Explicit unpin changes eligibility and may clear stale protected-exhaustion attention, but does not delete payload bytes; the next startup or admission performs reclamation. `/storage` and `/status` remain read-only. Grace, preservation/retirement-blocked, pinned, and other protected records remain untouched.
- Reclamation persists an exact per-session intent before deleting the deterministic app-local payload directory. Restart after deletion but before record commit proves absence and completes the same intent. The compact record retains Mission/session/outcome identity, Worktree Identity, sizes, manifest hash, expiry, and reclaimed disposition.
- Protected or pinned exhaustion persists `snapshot-storage-exhausted` attention and blocks new Retirement Unit admission. The blocker appears prominently in Mission Work and resolves after an unpin or policy change makes reclamation possible. Active-Mission storage inspection reports policy, payload/reserved/committed/available bytes, counts, expiry order, largest retained payloads, bounded reclamation history, and blockers.
- Verified snapshots created before Issue #68 remain readable. Their storage metadata is derived conservatively from the verified Preservation Budget timestamp or immutable manifest time when policy first needs it, then becomes durable on mutation.

## Blocked Actions and Replay

`retirement-inspect` exposes the exact unit revision, phase, terminal outcome, blocker, Worktree Identity, runner boundary, Preservation Budget, compact Retirement Record, and only actions that can actually run. Mission Work renders those inspection facts directly instead of routing a control to a nonexistent Operations Workspace view. `retirement-pin` changes retained payload policy, records the new pin field, and advances the session revision. `retirement-retry` persists intent, shares the destructive-effect lock, and directly performs a fresh bounded preservation or retirement attempt before applying outcome policy.

`retirement-export` permanently claims one normalized destination across Mission namespaces before persisting the exact correlation, revision, export kind, source/parent/runtime identities, and manifest/tree digest. A `retirement-blocked` unit reconstructs its verified Snapshot Payload. A `preservation-blocked` unit exports the exact independently quiesced managed path even when broken Git metadata or preservation's entry ceiling caused preservation to block; one canonical 32 MiB recovery-metadata representation fingerprints and re-verifies files, modes, directories, symlinks, and arbitrary replacement `.git` data without following links, while a proven Git administration pointer is projected out of the user export. Both export kinds require a nonexistent destination outside the retained source and complete app-private runtime root.

Materialization occurs through an open descriptor into a deterministic private sibling stage whose attempt is durably reserved before creation and then bound to exact anchor/payload device and inode identities. Publication uses the bound parent, exclusive no-replace rename, source-inode proof immediately around the syscall, substituted-source restoration, exact marker and top-level reproof, and recursive file/directory durability barriers before the receipt. A crash can consume at most two named attempts; foreign collided or replaced stages are preserved. Exact six-field intents written by the previous implementation remain loadable: an absent destination migrates to the current stage protocol, a complete legacy destination is adopted only after descriptor-bound marker/repository proof, and partial or foreign legacy data is left untouched. Any changed export remains blocked and is never overwritten.

Retained Worktree Discard requires the exact session id as confirmation, an explicit reason, a terminal blocked unit, fresh independent Runner Quiescence and open-handle absence, the deterministic managed worktree path, exact root identity and a bounded full-tree manifest, and Coding Workspace exclusion. It persists those boundaries before moving/removing the exact path. Snapshot-backed Git cleanup remains non-force; explicit no-snapshot discard may force-remove the separately fingerprinted exact Git worktree, or isolate and delete the exact managed directory when broken metadata prevents Git identity proof. Restart accepts only a remaining exact subset of the authorized manifest, so partial forced-Git or directory deletion can resume without accepting replacement bytes. Broken-Git fallback removes and verifies the exact stale registration. It proves final path and applicable Git-registration absence, records the irreversible outcome, and releases a still-bound Preservation Budget only after deletion. Pin, retry, export, and discard share the per-session effect lock, so no concurrent blocked action can strand an already completed deletion. Exact correlation replay never repeats an effect or overwrites newer canonical state; changed-boundary reuse fails closed.

Every persisted action receipt is validated against its action-specific shape, exact Mission/session owner, owning session revision, and exact discard confirmation during runtime load. The four meaningful mutations also pass through typed Workstation authority in Mission Work and the desktop bridge, use the session lifecycle revision, and append one Mission/session-linked Activity Journal entry. If the core effect commits before the Workstation receipt, exact correlation replay recovers the canonical effect and completes the missing audit side effects once.
