# Issue #70 — Local Inference Profile qualification and promotion

## Outcome

Issue #70 adds a bounded qualification workflow for Local Inference Profiles. It evaluates repeated governed fixture observations and reviewed task quality plus goal-to-reviewed-Evidence-Package latency. It does not treat raw token speed, prompts, model streams, plans, Evidence Packages, authority decisions, or source-dependent outcomes as cache truth.

## Implemented boundary

`albert_mvp.inference_qualification` is the public qualification seam:

- `build_governed_fixture_family()` returns the stable v1 family for discussion, routing, small and multi-file edits, repair, malformed output, policy violations, cancellation, long context, model swaps, and queued Local Agents.
- `InferenceQualificationService.qualify()` runs each fixture repeatedly through a supplied governed runner and retains only bounded outcome flags, validity counts, decomposed load/prompt-evaluation/first-token/decoding timings, reviewed latency, model digest, exact runtime-pin identity, and digest-keyed context/prefix measurements. Reviewed latency is retained only for accepted or repaired outcomes; a valid cancellation may carry null stage timings. The runner must echo the exact runtime pin supplied for the cohort; all control errors—including expected cancellation/deadline control, runner failure, invalid results, and context overflow—cannot count as reliable evidence even when an outcome happens to match the fixture. Invalid runner objects are recorded distinctly from runner exceptions. Cancellation is checked before context selection and before/after each cooperative runner call, including failed calls, while provider-specific calls receive the deadline seam for their own bounded execution. Combined selected context plus fixture suffix is admitted against the profile's prompt headroom. Reusable context-prefix reuse persists its digest and is measured independently from each fixture's suffix.
- `ContextProfilePlanner`, `compare_context_profiles()`, and `default_context_profiles()` compare bounded controller (8,192 → 16,384) and normal-worker (16,384 → 32,768) context sizes. Expansion is selected only when required material fits after output headroom and reviewed quality or reliability improves.
- `DeterministicContextSelector` keys reusable selection only by role, bounded budget, required source ids, and source digests. `PromptPrefixReuseTracker` reports exact-prefix reuse and invalidation; changing a source changes the digest and invalidates the prefix observation.
- `QualificationReportStore` atomically persists bounded report metadata below `runtime_root/inference/qualification/`, serializes promotion state under a cross-process lock, pins the exact Profile/runtime/binary/configuration digests in both the report and every observation, requires the canonical fixture family and definition digests/repetitions, an existing comparable stored baseline, and a service-issued rollback-test receipt bound to an existing restored report, the candidate/runtime identity, and the previous-restored report identity. Reload revalidates the stored rollback target, report-root shape and exact field allowlists, derived outcome flags, finite accepted/repaired timings, reviewed-latency eligibility, and sequential prefix digest semantics. Atomic report/state writes fsync the temporary file and parent directory, translate replace failures to typed `PromotionError` values, and clean only bounded owned temporary artifacts. The cooperative rollback callback receives the same cancellation/deadline control seam; missing or mismatched stored restore evidence remains non-promotable, and promotion binds the receipt target to the qualified baseline used for comparison. Inspection verifies that an active/previous pair is continuous with the active report's rollback receipt, rejects a promotion-ready active report with no retained target, and replays every promotion/rollback history entry—including final active/previous state—from its referenced reports and revision before mutation. Promotion also compares canonical Profile configuration including the exact model digest and complete p50/p95 reviewed latency evidence against the baseline, rejects withdrawn or non-inferior candidates, supports correlation/revision-guarded exact promotion and rollback replay, and retains the predecessor chain when rolling back to another promotion-ready report. Report files, context cache bytes, and promotion history are each bounded; incomplete or semantically invalid history cannot be mutated and exhausted histories fail closed so old correlation ids cannot be silently evicted. Deeply malformed bounded JSON and invalid UTF-8 identities are converted to typed persistence errors rather than leaking recursion or encoding failures.
- The one-process CLI and persistent newline transport expose the same `inference-qualification`, `inference-qualification-promote`, and `inference-qualification-rollback` projections over that store.

The promotion state remains scheduling/profile configuration metadata. Python Mission, session, file, command, Evidence Package, review, and accepted-state authority remains unchanged.

## Follow-up boundary

The report store is intentionally separate from Mission runtime authority. A later product surface may expose report inspection or connect promotion state to profile selection, but it must preserve the same exact runtime pin, rollback, and no-source-truth-cache rules.
